Understand the idea

Learning target: Understand addresses on interfaces, multiple interfaces on one host, and multiple addresses on one interface.

An address belongs to a network context

An IP address identifies an IP endpoint within an addressing and routing context. It is associated with an interface in common host configuration. Saying that a machine has one address is convenient, but a machine may have several interfaces and each interface may carry several addresses. IP address count therefore does not reveal interface count.

Addresses are not permanent hardware identities

An interface can receive a new address after configuration changes or lease renewal. A cloud public address may be mapped to a private address by the platform and may not appear directly in the guest's address list. Two isolated networks can reuse the same private address without referring to the same machine. Once networks are connected, overlap creates routing and identification problems.

Find the selected source address

A host with several addresses still needs to select a source for a particular outgoing flow. Routing and source-selection rules influence that choice, and applications can sometimes bind a chosen source. The address you find first in ip output is not guaranteed to be the source used for every destination.

Practical troubleshooting

Symptom

An allow rule contains the wrong client source IP.

Evidence that narrows the cause

Compare the actual selected source and any NAT with the address assumed by the rule.

Next action and verification

Update the documented traffic tuple based on observed source addresses.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
