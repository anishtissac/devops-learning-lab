Understand the idea

Learning target: Separate the device from the application. Follow a request and its response.

Client and server are roles

A client starts an interaction with a service. A server application accepts and processes requests for that service. These names describe roles in an exchange. The same machine can run a web server and act as a client to a database. A server is therefore not necessarily a special physical computer.

Separate machine, process, and service

A machine supplies computing resources and a network stack. A process is a running program. A service is the useful function a program offers, such as serving a webpage or answering a database query. Later, ports will identify transport endpoints used to reach these applications. For now, keep the machine and its running programs separate in your drawing.

Follow both directions

For a request and response interaction, the client must reach the server and the response must reach the client. An application can also initiate additional requests while serving the first one. A website may contact an authentication provider or database. A healthy front-end process does not establish that these dependencies work.

A web application reads a database.

  2. The web application becomes a client of the database.
  3. The database returns data to the web application, which prepares a separate browser response.
