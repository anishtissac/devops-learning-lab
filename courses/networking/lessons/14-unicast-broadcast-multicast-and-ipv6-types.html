Understand the idea

Learning target: Compare ways to address receivers and introduce IPv6 global, unique-local, and link-local addresses.

Unicast selects one addressed destination

Most familiar client-to-service traffic uses a unicast destination. Delivery still depends on routes and the endpoint. IPv6 anycast uses an address assigned at multiple locations and routing chooses an instance; it is not an instruction to deliver the same packet to every instance.

Broadcast and multicast select groups differently

An IPv4 local broadcast reaches the relevant broadcast domain. Routers do not normally forward local broadcasts as ordinary routed unicast. Multicast addresses identify a receiver group, and forwarding depends on multicast support and membership. IPv6 does not use broadcast; multicast handles several group and discovery functions instead. A group destination is not a guarantee that every physical machine will process the packet.

IPv6 address type matters

Global unicast supports globally scoped addressing when routed. Unique-local addresses fall under fc00::/7, with locally assigned deployments generally using fd00::/8. Link-local addresses have local-link scope. A host can hold several IPv6 addresses for different purposes. Read scope and routes before assuming which one is appropriate for a service.

Practical troubleshooting

Symptom

A multicast application works on one link but not another.

Evidence that narrows the cause

Check membership and multicast forwarding support, not only unicast routes.

Next action and verification

Verify the group-delivery design across each boundary.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
