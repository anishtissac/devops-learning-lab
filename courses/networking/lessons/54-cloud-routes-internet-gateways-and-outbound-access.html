Understand the idea

Learning target: Compare public and private subnet patterns and follow Internet, NAT, and service-access paths.

A cloud route associates a destination with a target

Subnet or attachment routing configuration directs matching traffic toward supported gateways or other targets. The provider virtual router and guest routing cooperate; inspecting only the guest's default route does not reveal every cloud forwarding decision.

Internet and NAT access serve different patterns

An Internet gateway supports the provider's Internet connectivity model. A NAT gateway commonly provides outbound connectivity for privately addressed workloads without making them ordinary unsolicited inbound destinations through that NAT. The instance still needs a route toward the chosen target and compatible traffic rules. A NAT gateway does not substitute for DNS or an application listener.

Private service access can use another path

Provider service gateways or private endpoints can route service traffic without the same public Internet path. Exact targets and capabilities depend on the platform and resource. Draw the destination-specific route and effective source, then include return and stateful handling rather than assuming every outbound request uses one gateway.

Practical troubleshooting

Symptom

The guest has a default route, but outbound traffic still fails.

Evidence that narrows the cause

Inspect the cloud route association, gateway target, source handling, and traffic rules.

Next action and verification

Repair the failed cloud-side condition after confirming the guest lookup.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
