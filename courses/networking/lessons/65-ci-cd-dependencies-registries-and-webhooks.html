Understand the idea

Learning target: Follow a runner to source control, package repositories, image registries, and deployment endpoints.

A pipeline is a graph of network dependencies

A runner may fetch source, resolve packages, download images, request credentials, call deployment APIs, and send notifications. Success at one dependency does not establish access to the next. Some steps run in containers with different network or proxy settings from the runner host.

Separate data transfer from identity errors

A TLS failure, registry authentication rejection, HTTP rate limit, and download timeout are different observations. A 401 or 403 response usually indicates a responding HTTP endpoint, not simple proof of an absent network route. Redirected artifact downloads can contact additional hostnames beyond the initial registry or repository.

Reproduce inside the actual job context

Use the runner or build container's resolver, proxy settings, trust store, and destination path. Do not assume an interactive administrator shell uses the same environment. Record dependency names and stages while keeping secrets, tokens, and private repository contents out of shared diagnostic notes.

Practical troubleshooting

Symptom

The same URL works from an administrator shell but fails in CI.

Evidence that narrows the cause

Compare namespace, resolver, proxy, trust store, credentials, and service identity in the job.

Next action and verification

Repair the actual job-context condition, then rerun the narrowly affected stage.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
