Understand the idea

Learning target: Borrow prefix bits, calculate the new ranges, and verify that the subnets fit.

Borrowing prefix bits creates smaller blocks

Dividing a parent prefix into equal child prefixes fixes more address bits. Extending /24 to /26 adds two prefix bits and creates 2^2 = 4 children. Each child contains one quarter of the parent's addresses. The child blocks must remain inside the parent and must not overlap.

List every boundary

For 192.168.8.0/24 divided into /26, starts are .0, .64, .128, and .192. Their final addresses are .63, .127, .191, and .255. Listing both ends catches skipped ranges and accidental overlap. Conventional host ranges exclude the first and last address of each child, not only those of the original parent.

Allocation is not connectivity

Creating address ranges on paper does not connect them. Traffic between child IP networks needs an appropriate routing design. Using a larger parent in documentation does not mean every host should keep the parent's broad interface prefix. Host configuration, routing, and the intended network boundaries need to agree.

See the relationships

Work through one example

Split 10.8.0.0/24 into four equal networks.

  1. Four children require two additional prefix bits, so each child is /26.
  2. Allocate 10.8.0.0/26, .64/26, .128/26, and .192/26.
  3. Each has 64 total addresses and 62 conventional host addresses. Together they cover the parent exactly.

Practical troubleshooting

Symptom

Two teams receive overlapping child blocks.

Evidence that narrows the cause

Compare the full numeric ranges, not just their labels.

Next action and verification

Reallocate disjoint aligned ranges before provisioning resources.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
