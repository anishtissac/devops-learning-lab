Understand the idea

Learning target: Understand point-to-point and host-prefix cases, then account for provider-specific reserved addresses.

A /31 is a special point-to-point case

A /31 contains two IPv4 addresses. RFC 3021 permits both as endpoint addresses on supported point-to-point links instead of applying the ordinary network-and-broadcast subtraction. This is a deliberate exception, not evidence that every multi-access subnet should use both boundaries as hosts.

A /32 names one IPv4 address

A /32 prefix fixes all 32 bits. It is useful for host routes and address-specific configuration. It contains one address, with no varying host bits. It does not create a conventional multi-host subnet with a gateway and a broadcast address. The surrounding routing and link design explain how it is reached.

Cloud reservations are platform rules

Standard AWS VPC IPv4 subnets reserve the first four addresses and the final address, giving eleven assignable addresses in a /28. OCI IPv4 subnets reserve the first two and the final address, giving thirteen in a /28. Platform-supported prefix ranges and specialised exceptions matter. Always check the current provider rules for the resource type you will provision.

Practical troubleshooting

Symptom

A request needs twelve instances in a standard AWS /28.

Evidence that narrows the cause

The sixteen-address block normally provides eleven assignable instance addresses under these rules.

Next action and verification

Choose an adequately sized supported subnet and leave operational headroom.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
