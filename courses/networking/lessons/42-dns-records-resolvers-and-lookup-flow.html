Understand the idea

Learning target: Explore A, AAAA, CNAME, PTR, and other common records, caching, and host lookup order.

DNS answers typed questions about names

An A record supplies IPv4 address data and AAAA supplies IPv6 address data. CNAME refers to another canonical name. PTR supports reverse-name lookup. Other record types carry service or policy information. A name can have several records, so one hostname does not imply one permanent IP address.

Resolvers and authoritative servers have different jobs

A client commonly asks a recursive resolver. That resolver can answer from cache or obtain authoritative data through the DNS hierarchy. Cached records remain usable according to their lifetime. NXDOMAIN means the queried name does not exist in that response context; NOERROR with no requested data is a different result. Timeout and SERVFAIL do not mean exactly the same thing.

Host lookup can involve more than DNS

Linux applications may use configured name-service sources such as files and DNS. getent follows the host's configured lookup path, while dig makes DNS queries. Split-horizon DNS can deliberately return different answers by resolver context. Compare the answer actually used by the failing application with the intended destination.

Practical troubleshooting

Symptom

dig returns an address but the application uses a different endpoint.

Evidence that narrows the cause

Compare name-service configuration, application cache, address family, and resolver context.

Next action and verification

Correct the actual lookup source or stale application state based on the evidence.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
