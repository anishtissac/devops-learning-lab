Understand the idea

Learning target: Compare connected, specific, and default routes and choose the most specific matching prefix.

A routing table contains destination prefixes

A route associates a prefix with forwarding behaviour, such as a local interface or a gateway. A connected route covers a directly attached range. A host route can cover a single address. A default route covers /0 and is eligible when no more specific matching route is selected in the relevant lookup.

Longest matching prefix is most specific

Within the simplified single-table model, compare all matching destination prefixes and choose the longest. A /25 match wins over a /24 match, which wins over a /0 match. A lower metric does not make a default route outrank a more specific route simply because the metric number is smaller.

Linux can apply policy before this comparison

Rules can choose tables using source, marks, interfaces, or other context. Equal-prefix route preferences and multipath can also matter. Begin with longest-prefix reasoning, then inspect ip rule and the relevant tables when ordinary assumptions do not explain the observed path. ip route get reports a lookup, not an active reachability probe.

Practical troubleshooting

Symptom

A default route change does not affect one destination.

Evidence that narrows the cause

Look for a more specific route or a policy-selected table.

Next action and verification

Identify the actual matching route before changing another default.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
