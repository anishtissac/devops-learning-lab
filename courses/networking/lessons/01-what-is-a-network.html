Module 1 · Network foundations

What is a network?

A network connects devices so they can exchange data. Understanding the devices, their connections, and the path between them is the first step in understanding network traffic.

01 / Start with the idea

Why do devices need a network?

A laptop can store a document on its own disk. Another computer cannot read that document directly from the laptop's memory or disk. The computers need a way to exchange the data.

A network provides connections between devices. Software on those devices uses the connections to send and receive data. That data could be a short message, a document, a database request, or part of a video.

Definition: A computer network is a set of connected devices that can exchange data using agreed communication rules.

Examples include a laptop sending a document to an office printer, an application server sending a query to a database server, and an AI application sending a request to a model service.

The purpose is the same in each case: data must travel from one device or service to another.

What does “connected” mean?

There must be a path that can carry the data. A path can use an Ethernet cable, a Wi-Fi connection, or several links and network devices. Cloud networks also provide virtual connections implemented by software and physical infrastructure.

The path also needs working configuration. A device can have a cable plugged in and still fail to communicate because of addressing, routing, access rules, or an application problem. We will examine each of these later.

02 / Name the parts

Devices, links, and shared rules

TermPlain explanationExample
DeviceA system that sends, receives, or forwards data.Laptop, phone, server, printer, switch, or router.
End deviceA device where the data is created or used.A laptop opens a file that a server sends.
LinkA connection between devices that carries data.An Ethernet cable or a Wi-Fi connection.
PathThe sequence of links and devices that data follows.Laptop → switch → file server.
ProtocolRules that describe how communication works.How a message is formatted and how the receiver interprets it.

What is data?

Data is information represented in a form that a computer can process. A text message, an image, and a database query are all data. Computers represent data using bits: values of 0 or 1.

A network carries signals that represent these bits. For example, a cable can carry electrical or optical signals, and Wi-Fi uses radio signals. Software at the receiving device interprets the data so an application can use it.

Why do protocols matter?

A physical connection does not tell a receiver how to interpret a message. Devices need compatible rules for communication. For example, the receiver needs to know which parts of the incoming data describe the message and which parts contain its contents.

You will meet protocols such as IP, TCP, UDP, DNS, and HTTP later. For now, remember that a protocol is a set of rules, rather than a physical cable or a particular device.

Useful picture: The link carries data. The protocol defines how devices communicate over that connection. Real networking uses several protocols together.

What do common network devices do?

Switch

Connects devices on a local Ethernet network and forwards traffic between them.

Wireless access point

Lets devices join a network using Wi-Fi. It commonly connects wireless devices to a wired network.

Router

Forwards traffic between different IP networks. A home router often connects a home network to the Internet provider's network.

Home networking box

Often combines router, switch, Wi-Fi access point, and firewall functions in one physical device.

The physical box and its jobs are different ideas. One box can perform several jobs. In a data center or cloud, those jobs may be spread across many physical or virtual components.

When reading a diagram, ask: What are the end devices? Which links connect them? Which devices forward the traffic? Where does the data need to go?

04 / Understand the scope

A local network can work without Internet access

A local area network, or LAN, commonly connects devices within a home, office, or site. The Internet connects many independently operated networks around the world.

Suppose your laptop and a file server are on the same local network. Your laptop can communicate with that server when the local path, device configuration, service, and access rules permit it. That exchange does not need to travel through the public Internet.

RequestExample pathNeeds the Internet?
Open a file on a local serverLaptop → local switch → local serverNo, for this local path.
Use an external websiteLaptop → local network → gateway → provider networks → websiteYes, for this public Internet path.
App calls a private cloud databaseApplication → configured private network path → databaseThe design can use a private path.

Why “connected to Wi-Fi” does not prove Internet access

The Wi-Fi connection joins your device to a local network. The local network's connection to other networks is a separate part of the path. Your device may remain connected to Wi-Fi while the Internet connection is unavailable.

Access rules also matter. Two devices can join Wi-Fi and still be prevented from communicating with each other, for example on a guest network with client isolation.

How does this connect to cloud and AI work?

A virtual cloud network gives cloud resources a configured network environment. Services may communicate over private paths, public Internet paths, or a mixture. The same questions still apply: what sends the data, what receives it, and what path connects them?

An AI application that calls a model endpoint also depends on a network path. If a request fails, you need to identify which part failed. A generic “network issue” is the beginning of an investigation.

    06 / Practise reasoning from evidence

    What does a working path tell you?

    Start with two questions: what works, and what fails? Comparing the paths helps you choose the next part to investigate.

    Case A: The local file server works, but the Internet service fails.

    The successful local request is evidence that the laptop can reach that server over its local path for that traffic. Investigate the additional components used by the Internet request: the gateway, Internet connection, external path, and destination service.

    In this lesson's model, load “Internet down”. The local destination succeeds and the Internet destination fails. In a real system, this pattern suggests a direction for investigation; it does not identify one guaranteed cause.

    Case B: The Internet service works, but the local file server fails.

    The laptop has a working path to that external service for that request. Focus next on the local server's connection, its service, and any rule affecting traffic to it.

    In this model, load “Server disconnected”. The local request fails, while the Internet request can still succeed.

    Case C: The device is connected, but the request is blocked.

    A connection gives traffic a possible path. Access rules decide which traffic can use it. A rule can block communication even when the cables, Wi-Fi, and devices are working.

    Load “Traffic blocked” and send the message. Restore “Allow the selected traffic” and compare the result.

    Practical observation exercise

    1. List three devices you use: for example, a laptop, router, and phone.
    2. Write down how each connects: cable, Wi-Fi, or another link.
    3. Choose one local destination and one external destination.
    4. Draw the path to each using labelled boxes and connections.
    5. Use the simulation to predict which destination is affected when one connection fails.

    You do not need to change a real machine's network settings for this exercise. The objective is to identify components and compare paths.

    07 / Explain the idea in your own words

    Check your understanding

    1. What makes connected devices a network?

    Show an example answer

    The devices have connections and compatible communication rules that let them exchange data. The path and configuration must support the exchange.

    2. What is the difference between a link and a protocol?

    Show an example answer

    A link carries data between devices. A protocol defines rules for communication, such as the structure and interpretation of messages.

    3. If Wi-Fi still shows “connected”, can Internet access be unavailable?

    Show an example answer

    Yes. The Wi-Fi connection reaches the local network. The local network's connection to other networks can fail separately.

    4. Why can a local file transfer work while a request to an external service fails?

    Show an example answer

    The two requests use different paths. The local transfer can stay inside the local network, while the external request depends on additional components and networks.

    5. What evidence would you collect before saying “the whole network is down”?

    Show an example answer

    Identify the source and destination, the request being tested, what succeeds, what fails, and which path each uses. The failure of one request alone does not prove that every network path has failed.

    08 / Keep these ideas

    Lesson recap

    • A network connects devices so they can exchange data.
    • Links carry data. Protocols define communication rules.
    • Switches connect devices locally; routers connect IP networks.
    • The Internet connects many networks.
    • A local path can work when Internet access is unavailable.
    • Troubleshooting starts by comparing the paths that work with the paths that fail.
