Subnet masks and network bits

Use binary masks to reveal the network portion of an IPv4 address.

Understand the idea

Learning target: Use binary masks to reveal the network portion of an IPv4 address.

A mask marks network positions

An IPv4 subnet mask contains leading one bits followed by zero bits. Ones select the prefix positions; zeroes mark the remaining host positions. For /24, the mask is 255.255.255.0. For /26, it is 255.255.255.192 because the last octet begins with two ones: 11000000.

Bitwise AND reveals the network

AND produces one only when both input bits are one. Applying it to an address and mask retains prefix bits and clears host bits. For 192.168.1.150/26, the last-octet operation is 10010110 AND 11000000 = 10000000, decimal 128. The resulting network is 192.168.1.128/26.

A larger prefix has fewer host positions

Moving the boundary right fixes more leading bits. It therefore makes the address block smaller, not larger. /28 describes a smaller block than /24. Valid CIDR masks are contiguous; a pattern with unrelated one bits scattered after zero bits is not the ordinary prefix model used here.

Work through one example

Build the /28 mask.

  1. The first 24 bits are ones, giving 255.255.255.
  2. Four additional ones in the final octet sum to 128 + 64 + 32 + 16 = 240.
  3. The complete mask is 255.255.255.240. Four host bits remain, giving 16 total addresses.

Practical troubleshooting

Symptom

A /28 is described as having 28 host bits.

Evidence that narrows the cause

The prefix counts network bits, not host bits.

Next action and verification

Subtract the prefix from 32 to find the remaining host positions.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.

Check your understanding

How many host bits remain in IPv4 /26?

Reveal the explanation

Six host bits remain: 32 − 26 = 6. The block contains 64 total addresses.
