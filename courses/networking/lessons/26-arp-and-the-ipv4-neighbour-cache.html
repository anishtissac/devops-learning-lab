Understand the idea

Learning target: Follow an address-resolution exchange and interpret neighbour entries and states.

ARP resolves a local IPv4 next hop

After routing chooses a next hop on an Ethernet link, the sender may need that neighbour's MAC address. Address Resolution Protocol asks which local attachment owns the selected IPv4 address. A request is commonly broadcast on that link and a reply supplies the mapping. ARP does not discover every router on an Internet path.

The neighbour cache avoids repeating every lookup

Linux keeps neighbour entries so it can reuse recent mappings. REACHABLE indicates recent reachability confirmation. STALE means the entry exists but recent confirmation has aged; it is not automatically a failure. INCOMPLETE and FAILED are more relevant when resolution has not obtained a usable mapping. State changes should be interpreted alongside actual traffic.

Resolve the gateway for a remote destination

If 192.0.2.20 is reached via 10.0.1.1, the relevant first-link neighbour is 10.0.1.1. A missing ARP entry for the remote service is normal. Virtual networks may use proxy or platform-managed resolution, so a familiar physical-LAN picture does not explain every cloud implementation detail.

Practical troubleshooting

Symptom

Traffic fails and the gateway neighbour remains INCOMPLETE.

Evidence that narrows the cause

Check the selected next hop, link, VLAN, and expected gateway presence.

Next action and verification

Repair the local next-hop problem before investigating the remote application.
