Understand the idea

Learning target: Identify endpoints, switches, routers, access points, cables, and wireless links.

Endpoint and intermediary

An endpoint creates or consumes application data. A laptop, phone, virtual machine, or database host can be an endpoint. An intermediary moves or controls traffic between endpoints. A switch connects devices on a local network. A router forwards packets between IP networks. A home Wi-Fi router often combines several functions in one box; the functions remain different.

Links form a path

A link is a connection between network attachment points. It can use copper, fibre, radio, or a virtual connection inside a host. A path is the ordered set of links and forwarding decisions used to reach a destination. The path to a nearby printer can differ from the path to a cloud service, even when both requests begin on the same laptop.

Draw functions before product names

Begin a drawing with the sender and receiver. Add the switches, gateways, and service entry points actually crossed. Label a link with what you know, rather than assuming that an icon proves connectivity. A solid cable does not prove that an application is listening. In cloud networks, several forwarding functions may be implemented by software rather than by a box you can inspect.

A laptop opens a local file service.

  1. The laptop sends through its network interface.
  2. A switch forwards local traffic toward the service host.
  3. The service application receives the request and sends a response. An Internet connection is not required for this local example.

Practical troubleshooting

Symptom

A local service works while an Internet site fails.

Evidence that narrows the cause

Compare the shared local path with the extra gateway and upstream path.

Next action and verification

Investigate the additional path before changing the working local service.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.

Check your understanding

Does a working laptop-to-switch link prove the remote application works?

Reveal the explanation

No. It proves only one part of the path. The destination, service, access rules, and response path still matter.
