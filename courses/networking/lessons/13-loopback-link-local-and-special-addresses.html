Understand the idea

Learning target: Explore 127.0.0.1, 0.0.0.0, link-local ranges, and cloud metadata endpoints in context.

Loopback addresses select the local context

IPv4 127.0.0.0/8 is loopback space, with 127.0.0.1 commonly used. IPv6 uses ::1. A request to loopback remains inside the current host network namespace. This is useful for local services and tests. It cannot select another host's loopback simply because the same written address exists there.

Link-local has a limited scope

IPv4 link-local space is 169.254.0.0/16, used for local-link functions rather than ordinary Internet routing. IPv6 link-local addresses use fe80::/10 and often require an interface scope when several links are possible. The cloud metadata address 169.254.169.254 is a provider-defined virtual endpoint. It does not imply a public server or a physical metadata machine on your guest's cable.

Unspecified and documentation addresses

0.0.0.0 can represent an unspecified IPv4 address and is commonly used as a wildcard bind. It is not a useful public client destination. A route written 0.0.0.0/0 means the default prefix, a different use of notation. Documentation examples use blocks such as 192.0.2.0/24; do not expect these example destinations to host a real service.

Practical troubleshooting

Symptom

A remote client cannot reach a loopback-only service.

Evidence that narrows the cause

Inspect the bind address and the namespace where the test runs.

Next action and verification

Use the intended service exposure design and a reachable address; opening unrelated rules will not fix the bind.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
