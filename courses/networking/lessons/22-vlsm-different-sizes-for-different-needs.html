VLSM: different sizes for different needs

Understand the idea

Learning target: Allocate larger subnets first and use Variable Length Subnet Masking to fit mixed requirements.

VLSM allocates different-sized blocks

Variable Length Subnet Masking uses different prefix lengths to meet different capacity needs. Reserving one identical large block for every team wastes address space when requirements vary. VLSM fits each requirement to a suitable power-of-two block while preserving alignment and avoiding overlap.

Calculate capacity in context

For conventional IPv4 host subnets, select enough total addresses to include required hosts plus the network and broadcast addresses. Sixty hosts need 64 total addresses, a /26. Thirty hosts need 32, a /27. Twelve hosts need 16, a /28. Cloud reservations change the capacity calculation, so do not reuse these exact host capacities blindly in a provider subnet.

Allocate largest blocks first

Sort requirements by required block size. Take aligned blocks from the parent, then place smaller blocks into the remaining space. Check the start, end, and parent containment of every allocation. Leave documented spare space for growth. A VLSM plan is an address allocation; it does not automatically produce a correct routing or access-control policy.

See the relationships

Work through one example

Allocate 60, 30, and 12 conventional hosts inside 10.20.0.0/24.

  1. Give 60 hosts 10.20.0.0/26, ending at .63.
  2. Give 30 hosts 10.20.0.64/27, ending at .95.
  3. Give 12 hosts 10.20.0.96/28, ending at .111. The space beginning at .112 remains unallocated.

Practical troubleshooting

Symptom

A plan fits host counts but fails cloud provisioning capacity.

Evidence that narrows the cause

The planner used conventional minus-two reservations instead of platform rules.

Next action and verification

Recalculate available capacity for the target platform before choosing prefixes.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.

Check your understanding

Why should the largest block usually be placed first?

Reveal the explanation

Its alignment and size are most restrictive. Placing it first reduces fragmentation that can prevent it fitting later.
