Understand the idea

Learning target: Read ip link, ip addr, ip route, and ip neigh as connected pieces of evidence.

Inventory before intervention

Record the failing source environment, time, destination, protocol, and symptom before changing anything. Start with link and address state, then inspect the selected route and next-hop neighbour. These observations describe related parts of the host's delivery decision. They do not need a restart to become useful.

Connect the commands into one explanation

ip -br link names attachments and their state. ip -br addr adds local addresses and prefixes. ip route get explains a specific lookup, while ip neigh concerns local next-hop resolution. Read the same interface and source across the outputs. A neighbour entry for the gateway is expected for an ordinary routed remote destination.

Compare with the intended design

A configured value can be syntactically valid but wrong for the environment. Check the intended prefix, gateway, address family, and namespace. Capture a working comparison when possible. Preserve the observations that justify a later change, so a successful result can be explained rather than guessed.

Practical troubleshooting

Symptom

An address is present, but the wrong gateway is selected.

Evidence that narrows the cause

The address inventory alone missed the route decision.

Next action and verification

Correct the intended route after confirming which table and rule produced it.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
