Understand the idea

Learning target: Draw the connections an intermediary makes and distinguish pass-through from termination.

A forward proxy acts for a client

A client-side proxy can mediate access to external services. The proxy's own routes, resolver, authentication, and egress matter. The original client may never connect directly to the final destination. Some applications honour proxy environment variables while others use their own settings.

A reverse proxy is a service entry point

It accepts client-facing traffic and forwards or creates upstream requests toward backends. It can terminate TLS, route by name or path, and add headers. A terminating design has separate client-to-proxy and proxy-to-backend connections. Client identity observed by a backend depends on the design and trusted forwarding metadata.

Load balancing selects destinations

A load balancer distributes eligible traffic among configured targets. Network-oriented and application-oriented products differ in forwarding, termination, source handling, and health checks. The product label alone is not a complete topology. Draw the actual connections and protocol boundaries, then test them independently.

Practical troubleshooting

Symptom

The proxy returns a gateway error.

Evidence that narrows the cause

Inspect the proxy-to-upstream connection, timeout, and backend response rather than only the user-to-proxy path.

Next action and verification

Correct the failed upstream condition and verify the original user request.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.

Check your understanding

Does a TLS-terminating reverse proxy necessarily use the client's same TCP connection to the backend?

Reveal the explanation
