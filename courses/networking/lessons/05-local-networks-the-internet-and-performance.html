Understand the idea

Learning target: Compare a local path with an Internet path. Build first mental models for latency and bandwidth.

Local and Internet describe different paths

A local network connects devices within a limited network context. The Internet joins many independently operated networks through routing. A local application does not inherently need the Internet. A browser may use the same local interface for a local service and for a remote service, but routing sends the remote traffic beyond that link.

Latency measures delay

Latency describes how long an operation or delivery takes. Round-trip time measures an exchange out and back. A 40 ms round trip means about forty milliseconds for that measured exchange; it is not automatically the complete time to load a page. Name lookup, connection establishment, server work, and data transfer add different delays.

Bandwidth and throughput are different

Bandwidth commonly describes a link's capacity in bits per second. Throughput is the rate actually achieved by a measured transfer. Contention, protocol overhead, congestion, receiver limits, and server behaviour can reduce it. Eight bits make one byte. A 100 Mbit/s link has a theoretical payload-free conversion of 12.5 decimal MB/s, before overhead and other limits.

See the relationships

Work through one example

Compare two links for a 10 MB download.

  1. At 100 Mbit/s, the raw serial transfer budget is 10 × 8 / 100 = 0.8 seconds.
  2. At 10 Mbit/s, the same raw budget is 8 seconds.
  3. A small request may instead be dominated by setup and server delay. A faster link does not remove those delays.

Practical troubleshooting

Symptom

Small API requests are slow on a high-capacity connection.

Evidence that narrows the cause

Compare setup and server delay with payload size; bandwidth may not be the limiting factor.

Next action and verification

Measure distinct timing stages instead of upgrading link capacity without evidence.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
