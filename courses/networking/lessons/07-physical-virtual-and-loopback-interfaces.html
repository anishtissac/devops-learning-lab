Understand the idea

Learning target: Recognise Ethernet, Wi-Fi, virtual adapters, bridges, and the local loopback interface.

Physical and virtual describe implementation

A physical interface is backed by a hardware connection. A virtual interface is supplied by software or a virtual device. Both can participate in packet delivery. A bridge joins link-layer attachments; a virtual Ethernet pair connects two interface endpoints; a tunnel adds another packet-delivery structure. These devices solve different problems even though Linux displays them through related tools.

Loopback stays inside a network namespace

The lo interface supplies local communication. IPv4 addresses in 127.0.0.0/8 and IPv6 ::1 refer to the local host context. A request to 127.0.0.1 never means the loopback interface of a different machine. A container normally has a separate network namespace, so its loopback belongs to that namespace rather than to the host's namespace.

Do not infer the whole topology from a name

Names such as docker0, veth1234, and tun0 are clues. Confirm the interface type and its relationships with detailed output and the relevant runtime. A virtual interface can be part of a working path even though no new physical network card was installed.

See the relationships

Work through one example

A host and container both use 127.0.0.1.

  1. A host-local service can listen on the host loopback.
  2. The container has its own loopback in the normal isolated network model.
  3. The container must use an appropriate host or published endpoint to reach the host service; its own 127.0.0.1 is a different destination.
