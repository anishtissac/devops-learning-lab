UDP: independent datagrams

Understand the idea

Learning target: Understand a connectionless transport and compare its trade-offs with TCP.

UDP preserves datagram boundaries

An application sends individual datagrams through UDP. The transport does not establish a TCP-style connection handshake or provide TCP's ordered retransmitting byte stream. Each datagram is a separate unit; the receiver can observe message boundaries if it receives the data.

Applications choose the additional behaviour

A UDP-based protocol can implement its own acknowledgements, retries, ordering, or congestion handling. QUIC is a prominent example of a richer protocol built over UDP, so UDP does not imply that all higher-level applications must be unreliable. Large UDP datagrams still face IP size and fragmentation limits.

UDP probing has limits

A missing reply does not establish whether a UDP port is open, filtered, or whether the application simply ignores an invalid message. Tools can report a completed local UDP send even when no meaningful service interaction occurred. Use a valid protocol request and interpret any ICMP feedback in context.
