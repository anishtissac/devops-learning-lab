Understand the idea

Learning target: Track which addresses or ports change and understand why connection state matters.

Translation changes packet addressing

Source NAT changes the source address, destination NAT changes the destination address, and port translation can change transport ports. These operations are different from an ordinary routing decision that forwards a packet toward its existing destination. A platform may perform several operations together, so name each change explicitly.

State makes replies find the original endpoint

A typical stateful outbound NAT remembers a relationship between an internal flow and its translated external flow. A reply addressed to the translated endpoint can then be mapped back. Many internal clients can share an external address when translated ports distinguish eligible flows. Real matching includes protocol and peer details, not just one port number.

NAT is not an application proxy or a complete policy

A terminating proxy creates another connection and may change application behaviour as well. NAT commonly rewrites packet headers without becoming the application server. Neither translation nor a private address alone proves that access is permitted or secure. Routing and explicit controls still matter.

Practical troubleshooting

Symptom

A remote allowlist expects the private source address.

Evidence that narrows the cause

Observe the actual translated or proxied source at the remote entry point.

Next action and verification

Align the documented allow rule with the connection that the remote service actually sees.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.

Check your understanding

Is destination NAT the same as changing the source address?

Reveal the explanation

No. DNAT changes the destination; SNAT changes the source. Port translation can accompany either design.
