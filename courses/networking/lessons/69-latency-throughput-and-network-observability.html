Understand the idea

Learning target: Break down request timing, compare bandwidth with application throughput, and connect logs, metrics, and traces.

Separate fixed delay from transfer rate

A small API response may be dominated by setup, queueing, or computation. A large artifact can be dominated by payload transfer. Link capacity is not the same as achieved application throughput. Compare payload size, connection reuse, round-trip time, and server processing before choosing an optimisation.

Many tool timings are cumulative

curl time_namelookup, time_connect, time_appconnect, and time_starttransfer are measured from the start of the transfer. For a fresh ordinary connection, differences between suitable cumulative milestones can approximate stage durations. Reuse, proxies, redirects, and protocol behaviour can complicate interpretation. Do not add all cumulative values as if each were an independent duration.

Use correlated observations

Logs explain application events, metrics show rates and distributions, and traces connect operation stages across dependencies. Compare percentiles and error rates rather than only an average. A long time to first generated token can involve queueing or model work after the network handshake has already completed.

See the relationships

Work through one example

Cumulative timings are DNS .020 s, TCP .060 s, TLS .100 s, and first byte .500 s.

  1. For this controlled fresh-connection example, the TCP stage after DNS is about .040 s.
  2. TLS adds about .040 s after TCP; the later request-and-server interval to first byte is about .400 s.
  3. The total to first byte is .500 s, not the sum of all four cumulative milestones.

Practical troubleshooting

Symptom

An engineer adds cumulative timings and reports an inflated total.

Evidence that narrows the cause

Compare the reported milestones with time_total and the tool documentation.

Next action and verification

Calculate appropriate differences and retain caveats about reuse, redirects, and proxy stages.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.

Check your understanding

Should cumulative DNS, connect, TLS, and first-byte times be summed to get first-byte total?

Reveal the explanation

No. First-byte time already includes earlier elapsed stages in the ordinary measurement.
