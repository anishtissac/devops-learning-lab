Understand the idea

Learning target: Separate each connection in an application-to-model-to-data path, including private access and proxies.

An AI request can create several service connections

A user-facing application may call an embedding model, search a vector database, retrieve documents, and request a generated answer from another model endpoint. Draw each connection with its own source, destination, protocol, port, identity, and timeout. The browser usually does not contact every internal dependency directly.

Private data paths and public API paths differ

A model service can be public, private, or reached through a proxy or gateway. DNS can select a private endpoint, while an application egress policy determines whether it can reach it. Data residency and intended egress boundaries are part of the architecture; an SDK setting does not by itself describe the network route.

Distinguish network wait from model work

A delayed response can include name lookup, connection setup, TLS, queueing, retrieval, model computation, and streaming. Receiving an HTTP response means progress occurred, but the status and stream still need interpretation. Retrying a completed or partially completed operation can duplicate work or cost, so application semantics matter.

Evidence that narrows the cause

Next action and verification
