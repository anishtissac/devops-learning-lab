Understand the idea

Learning target: Follow private service connections, name resolution, and instance-local metadata paths.

A private endpoint is an access path to a service

Depending on the provider and service, a private endpoint supplies network access through private addressing or a private service attachment. It does not eliminate routing, policy, DNS, or application identity requirements. The exact service and resource type determine the supported configuration.

DNS must direct the right clients to the right path

Private names or split-horizon answers can select the private endpoint. A client using a public resolver may receive a different address. Compare the actual answer used in the application environment with the intended endpoint and network path. A private address is not useful to a client lacking the route and permission to reach it.

Metadata is a different local service function

An instance metadata endpoint provides provider-defined instance information and, in some configurations, identity-related material. It is not the same as a private endpoint for your application API. Treat its reachability and request requirements as platform-specific; do not place real identity tokens in course notes.

Practical troubleshooting

Symptom

A private endpoint exists, but clients use the public address.

Evidence that narrows the cause

Inspect DNS zones, resolver forwarding, caching, and the client's actual lookup source.

Next action and verification

Correct the intended name-resolution path and verify the selected endpoint.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
