Understand the idea

Learning target: Build an IPv4 address from four octets. Convert between small binary values and decimal numbers.

An IPv4 address has 32 bits

A bit has two possible values, zero and one. Eight bits form one octet. IPv4 groups its 32 bits into four octets, commonly displayed as decimal numbers separated by dots. Each octet ranges from 0 through 255 because eight bits can represent 256 different values. An address such as 192.168.1.10 is a convenient written form of one 32-bit value.

Binary positions have weights

Read an eight-bit octet using the weights 128, 64, 32, 16, 8, 4, 2, and 1. Add the weight wherever the bit is one. Thus 11000000 is 128 + 64 = 192. Leading zeroes in a binary drawing keep the eight positions visible; they do not add value. Use this positional model instead of memorising isolated binary strings.

Why this helps subnetting

A subnet prefix counts bits from the left, across octet boundaries when necessary. Understanding bit positions makes /26 understandable: it fixes 24 bits in the first three octets and two more bits in the final octet. Decimal dots make addresses easier to read, but they do not limit where a valid prefix can end.

Work through one example

Convert the last octet 150.

  1. 150 contains 128, leaving 22.
  2. 22 contains 16, leaving 6; 6 contains 4 and 2.
  3. The active weights are 128, 16, 4, and 2: 10010110. Check the sum before continuing.

Practical troubleshooting

Symptom

An example uses 300 as an IPv4 octet.

Evidence that narrows the cause

Eight bits cannot represent decimal 300.

Next action and verification

Check each octet independently and correct the input; do not silently wrap the value.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.

Reveal the explanation
