Understand the idea

Learning target: Identify a flow by its addresses, ports, and transport protocol, and understand client-side port selection.

A socket is an operating-system communication endpoint

Applications use socket APIs to create and use communication endpoints. For an Internet transport, address family, local address, protocol, and port are relevant. A connected TCP socket also has a peer endpoint. A listening socket and its accepted client connections are different sockets with related local service addresses.

The five-tuple identifies a flow context

The usual transport five-tuple contains source IP, source port, destination IP, destination port, and protocol. Multiple clients can connect to the same server address and port because their full flow identities differ. Network namespaces and additional platform context can further distinguish otherwise similar tuples.

Ephemeral ports support outgoing connections

A client commonly gets a local source port from a configured ephemeral range. The exact range is platform configuration, not a universal constant. Ports can be reused in valid contexts; the practical connection limit is not simply one global 65535 counter. Large workloads may still encounter tuple, NAT, or state-table exhaustion.

Practical troubleshooting

Symptom

New outbound connections fail under high concurrency.

Evidence that narrows the cause

Inspect tuple use, ephemeral allocation, NAT capacity, connection lifetime, and application pooling.

Next action and verification

Locate the resource being exhausted before changing unrelated server listener ports.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
