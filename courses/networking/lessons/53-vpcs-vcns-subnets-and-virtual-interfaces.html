Understand the idea

Learning target: Map the concepts already learned to cloud network boundaries, instances, and attached interfaces.

A cloud network supplies a virtual addressing context

AWS VPC and OCI VCN are provider network constructs with subnets, routes, and attachments. They are not identical products, but familiar address and path reasoning applies. An instance's virtual interface attaches it to the relevant subnet and associates address and policy context with that attachment.

Read both control-plane and guest views

The cloud console or API describes provider resources. The guest shows its interfaces, local addresses, routes, and listeners. A public address can be mapped outside the guest, so the two views need not contain identical address strings. Use attachment identifiers and private addresses to correlate the views.

Subnet design includes capacity and reachability

Nonoverlapping ranges, reserved positions, routing associations, and intended exposure all matter. Private addressing alone is not a complete access-control policy. A subnet name such as public does not prove that a particular instance has the addressing, route, and permissions needed for an Internet exchange.
