Understand the idea

Learning target: Investigate an incorrect prefix, overlap, missing gateway, wrong route, and missing return path.

Case: a prefix classifies a remote address as local

Host A should use 10.0.1.10/24 and reach 10.0.2.20 through gateway 10.0.1.1. Instead it is configured with /16. That broad connected route covers 10.0.2.20. The host can therefore attempt local neighbour delivery rather than the intended gateway path. An application timeout is the visible symptom of an earlier addressing decision.

Predict the evidence before checking

Under the simplified ordinary-route case, ip route get for 10.0.2.20 selects the broad direct link. Neighbour resolution for the remote address can remain incomplete because that endpoint is not on this link. A more specific route or policy could change the outcome, so inspect actual selected routing instead of asserting that every broad prefix must produce one result.

Case: the forward route is correct but return routing is absent

If a request reaches the remote service and a response leaves toward an unintended gateway, changing the client prefix may be irrelevant. Read the effective source seen by the service and inspect the destination-side return route. Observations from both sides distinguish these two failures even though both can appear as client timeouts.

Verify the intended persistent fix

The chosen correction must match the approved address plan and configuration manager. Confirm local-subnet access, remote dependency access, and selected source after the change. A guessed temporary route can hide an incorrect persistent prefix without repairing the source of configuration.

Practical troubleshooting

Symptom

Remote traffic triggers neighbour resolution for a host known to be on another network.

Evidence that narrows the cause

Inspect the actual connected prefix and any explicit on-link route.

Next action and verification

Correct the intended persistent prefix or route through its configuration owner, then verify both directions.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
