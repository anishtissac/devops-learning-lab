Understand the idea

Learning target: Read methods, headers, status codes, and redirects while keeping transport reachability separate.

HTTP defines request and response meaning

A request identifies an operation with a method and target, along with fields and possibly content. A response includes a status code, fields, and possibly content. GET and POST express different semantics; a TCP port alone does not tell you whether a particular HTTP operation is permitted.

Status codes locate application behaviour

A 2xx response generally reports success at the HTTP level. A 3xx response redirects or provides related control information. A 4xx response reports a client-facing request problem, and a 5xx response reports a server-side condition. These categories do not mean the entire business workflow succeeded. An authentication redirect is different from a network timeout.

Redirects create additional requests

A Location field can send the client to another scheme, name, port, or path. That next request may need separate DNS, transport, and TLS access. curl without automatic redirect following exposes the initial response; following redirects changes which endpoints are tested. HTTP semantics apply across versions, while HTTP/3 uses QUIC rather than ordinary TCP transport.

Practical troubleshooting

Symptom

The first endpoint returns 302, but the user reports login failure.

Evidence that narrows the cause

Inspect the redirect destination and subsequent requests.

Next action and verification

Test the next hostname, path, TLS identity, and authentication response.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.

Check your understanding

Is an HTTP 404 the same as a failed TCP connection?

Reveal the explanation

No. A 404 is an HTTP response from a responding application or intermediary.
