Understand the idea

Learning target: Separate the host address from the application endpoint and distinguish source and destination ports.

Addresses locate IP endpoints; ports distinguish transport endpoints

Several programs can use one host address. TCP and UDP include port fields that help the stack deliver traffic to the appropriate socket. A port number is not a process ID and is not a physical connector. TCP port 53 and UDP port 53 belong to different transport namespaces.

Source and destination ports have different roles

A client commonly uses a dynamically selected local source port while contacting a known server destination port. The response reverses the transport endpoints. HTTPS often uses TCP 443, but a process can use another configured port. A familiar number is a convention, not proof of the protocol actually running there.

An open rule does not create a listener

A firewall can permit packets for a destination port while no process accepts them. Conversely, a local listener can exist while the path blocks remote traffic. Establish the destination address, transport protocol, port, namespace, and owning process separately.

Practical troubleshooting

Symptom

A security rule allows UDP while the application uses TCP.

Evidence that narrows the cause

Compare the exact transport protocol in the rule with the actual listener and request.

Next action and verification

Correct the intended traffic tuple; matching port numbers alone are insufficient.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
