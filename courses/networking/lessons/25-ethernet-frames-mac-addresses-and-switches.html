Understand the idea

Learning target: Distinguish IP delivery from local frame delivery and see how a switch learns where to forward frames.

Frames deliver on a local link

Ethernet uses frames with source and destination MAC addresses. A MAC address identifies a link-layer attachment in this context; it is not an Internet-wide route. The IP packet inside the frame can be destined for a remote network while the frame is addressed to the local gateway.

A switch learns from source addresses

A learning switch associates observed source MAC addresses with ports. It uses a known destination mapping to forward a frame toward the relevant port. Unknown unicast and broadcast handling can involve flooding within the permitted domain. A switch's forwarding table is different from a host's IP routing table.

Local headers change across routed hops

A router receives a local frame, processes the IP packet, and sends it through a new local-link frame on the outgoing network. The final remote service MAC address is not carried unchanged through every router. Without translation, the source and destination IP addresses can remain the endpoint addresses even while local MAC addresses change at each hop.

Work through one example

Host 10.0.1.10 contacts a service on another subnet.

  1. The route selects gateway 10.0.1.1.
  2. The first Ethernet frame uses the gateway MAC as destination.
  3. After routing, another frame carries the packet on the next link. The first frame does not need the remote service MAC.

Practical troubleshooting

Symptom

A neighbour entry contains the gateway MAC for traffic to a remote destination.

Evidence that narrows the cause

This is expected when the route selects the gateway as next hop.

Next action and verification

Distinguish the remote IP destination from the local frame destination.

Retest the original operation from the same source context. A successful test of a different endpoint or protocol does not establish that this symptom is resolved.
