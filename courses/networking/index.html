01 · Understand the foundations

01 Network foundationsDevices, connections, and the reason networks exist 5 lessons+

Learning outcome: Explain what connects two devices, what travels between them, and why communication can fail.

  1. 01
    What is a network?Read lesson →

    Devices exchange data through a path. Explore local communication and diagnose a broken connection.

  2. 02
    Devices, links, and network paths

    Identify endpoints, switches, routers, access points, cables, and wireless links.

  3. 03
    Clients, servers, and services

    Separate the device from the application. Follow a request and its response.

  4. 04
    Data, packets, and protocols

    Understand why data is divided into messages and packets, and why devices need shared rules.

  5. 05
    Local networks, the Internet, and performance

    Compare a local path with an Internet path. Build first mental models for latency and bandwidth.

Practical exercise

Draw a laptop, a local service, and an Internet service. Trace each path and explain what changes when one connection breaks.

02 Interfaces and IP addressesHow a device connects and how an interface gets an address 5 lessons+

Learning outcome: Distinguish a machine, an interface, and an IP address, including several addresses on one interface.

  1. 06
    Network cards and network interfaces

    Connect the physical network adapter to the interface that the operating system exposes.

  2. 07
    Physical, virtual, and loopback interfaces

    Recognise Ethernet, Wi-Fi, virtual adapters, bridges, and the local loopback interface.

  3. 08
    What an IP address identifies

    Understand addresses on interfaces, multiple interfaces on one host, and multiple addresses on one interface.

  4. 09
    IPv4, IPv6, and address assignment

    Compare the two address families and introduce static and automatic address configuration.

  5. 10
    Read your first Linux network output

    Interpret interface names, interface state, addresses, and prefixes in ip output.

Practical exercise

Read ip -br link and ip -br addr on a lab host. List each interface, its state, and every assigned address.

03 Address structure and address typesRead an address and understand its scope 4 lessons+

Learning outcome: Explain the structure of IPv4 and recognise why public, private, loopback, and link-local addresses behave differently.

  1. 11
    IPv4 octets, bits, and binary

    Build an IPv4 address from four octets. Convert between small binary values and decimal numbers.

  2. 12
    Public and private addresses

    Understand private address space, public reachability, and why an address alone does not guarantee access.

  3. 13
    Loopback, link-local, and special addresses

    Explore 127.0.0.1, 0.0.0.0, link-local ranges, and cloud metadata endpoints in context.

  4. 14
    Unicast, broadcast, multicast, and IPv6 types

    Compare ways to address receivers and introduce IPv6 global, unique-local, and link-local addresses.

Practical exercise

Classify a set of example addresses. Explain which addresses refer to this host, a local link, or another network.

04 Subnet masks and CIDRUnderstand the boundary between network bits and host bits 4 lessons+

Learning outcome: Read a prefix such as /24 or /28, convert it to a mask, and explain what the prefix describes.

  1. 15
    Why a network needs a prefix

    Separate an individual address from the address block it belongs to.

  2. 16
    Subnet masks and network bits

    Use binary masks to reveal the network portion of an IPv4 address.

  3. 17
    CIDR notation and prefix lengths

    Connect /24, /28, and other prefixes to masks, block sizes, and same-subnet comparisons.

  4. 18
    IPv6 prefixes and notation

    Read compressed IPv6 notation and understand how prefixes work with 128-bit addresses.

Practical exercise

Change a prefix in a visual model. Predict the address block size and test whether two IPv4 addresses share a prefix.

05 Subnetting, VLSM, and address planningCalculate address ranges and design a usable address plan 6 lessons+

Learning outcome: Choose subnet sizes, calculate ranges, and allocate address space without overlap.

  1. 19
    Network addresses, broadcast addresses, and host ranges

    Find the boundaries of a conventional IPv4 subnet and distinguish total addresses from host addresses.

  2. 20
    Subnet boundaries and block sizes

    Calculate ranges with a repeatable method and check addresses near a boundary.

  3. 21
    Split a network into equal subnets

    Borrow prefix bits, calculate the new ranges, and verify that the subnets fit.

  4. 22
    VLSM: different sizes for different needs

    Allocate larger subnets first and use Variable Length Subnet Masking to fit mixed requirements.

  5. 23
    /31, /32, and reserved addresses

    Understand point-to-point and host-prefix cases, then account for provider-specific reserved addresses.

  6. 24
    Overlaps, summaries, and a complete address plan

    Detect overlap, introduce route summarisation, and leave room for future growth.

Practical exercise

Divide an example network into application, database, and management subnets with different capacity needs. Explain each allocation.

02 · Follow the traffic

06 Local network deliveryMAC addresses, frames, neighbours, and network layers 5 lessons+

Learning outcome: Explain how a host delivers traffic to the next device on its local link.

  1. 25
    Ethernet frames, MAC addresses, and switches

    Distinguish IP delivery from local frame delivery and see how a switch learns where to forward frames.

  2. 26
    ARP and the IPv4 neighbour cache

    Follow an address-resolution exchange and interpret neighbour entries and states.

  3. 27
    Local links, VLANs, and broadcast domains

    Understand which devices share a local link and why a router is needed between networks.

  4. 28
    IPv6 Neighbor Discovery

    Compare the purpose of IPv6 neighbour discovery with the IPv4 mechanisms already learned.

  5. 29
    OSI, TCP/IP, and encapsulation

    Follow application data through transport, network, and link functions without assigning each device to only one layer.

Practical exercise

Compare ip route get with ip neigh. Explain why traffic to a remote IP uses the local gateway as its next link-layer neighbour.

07 Routing between networksChoose the path, follow the return, and understand translation 6 lessons+

Learning outcome: Predict a host's selected route and explain gateways, return paths, NAT, and packet-size problems.

  1. 30
    Gateways and IP forwarding

    Follow a packet beyond the local network and distinguish host routing from router forwarding.

  2. 31
    Routing tables and longest-prefix matching

    Compare connected, specific, and default routes and choose the most specific matching prefix.

  3. 32
    Source addresses and return paths

    Identify the outgoing interface and selected source IP, then check how the response finds its way back.

  4. 33
    NAT, SNAT, DNAT, and port translation

    Track which addresses or ports change and understand why connection state matters.

  5. 34
    MTU, fragmentation, and Path MTU Discovery

  6. 35
    ICMP, ping, and route tracing

Practical exercise

Read a routing table and use ip route get for several destinations. Draw the forward and return paths and locate a missing route.

08 Ports, sockets, TCP, and UDPGet traffic to the correct application 6 lessons+

Learning outcome: Interpret a listener or connection and separate address, protocol, port, and process.

  1. 36
    Why applications need port numbers

    Separate the host address from the application endpoint and distinguish source and destination ports.

  2. 37

    Follow the handshake, sequence numbers, acknowledgements, retransmissions, and connection close.

  3. 38
    UDP: independent datagrams

    Understand a connectionless transport and compare its trade-offs with TCP.

  4. 39
    Sockets, ephemeral ports, and the five-tuple

    Identify a flow by its addresses, ports, and transport protocol, and understand client-side port selection.

  5. 40
    Bind addresses and listening services

  6. 41
    Connection refused, timeout, reset, and port conflicts

    Turn a connection symptom into testable possibilities without treating one message as a complete diagnosis.

Practical exercise

Run a local service, inspect it with ss, compare loopback and interface listeners, and investigate a deliberate port conflict.

09 DNS and application protocolsFrom a hostname to an application response 6 lessons+

Learning outcome: Separate name lookup, connection setup, TLS negotiation, and application behaviour.

  1. 42
    DNS records, resolvers, and lookup flow

    Explore A, AAAA, CNAME, PTR, and other common records, caching, and host lookup order.

  2. 43
    DHCP and automatic configuration

    Follow address configuration and distinguish an address lease from routes and resolver settings.

  3. 44
    HTTP requests, responses, and redirects

  4. 45

  5. 46

  6. 47
    Proxies, reverse proxies, and load balancers

Practical exercise

Follow a request with getent, dig, and curl -v. Identify a DNS result, a connection, a TLS exchange, and an HTTP response.

14 Troubleshooting and design capstoneCombine the complete model and explain your evidence 5 lessons+

  2. 71
    Case study: the address or route is wrong

Practical troubleshooting, throughout.

Every module includes an exercise. These recurring cases connect a real symptom to the concept and evidence behind it.

Addressing and routes

“The server cannot reach the destination.”

Check the interface, address, prefix, selected route, gateway, and response path.

ip -br addrip route getip neigh
Name resolution

“The hostname does not resolve.”

Compare the host lookup with DNS records, resolver configuration, and the intended destination.

getent hostsdigresolver settings
Ports and listeners

“The process runs, but clients cannot connect.”

Inspect the listening address and port. Check the path and look for a competing process.

ss -lntpTCP probesservice logs
HTTPS and applications

“The connection works, but HTTPS fails.”

Separate TLS negotiation, certificate validation, HTTP redirects, and application errors.

curl -vopenssl s_clientHTTP status
Cloud and Kubernetes

“The backend is healthy, but users fail.”

Trace the user path separately from health checks. Inspect listeners, access rules, and endpoints.

route tablesbackend healthService endpoints

“The request starts, then times out.”

Break timing into name lookup, connection, TLS, response, and streaming across each dependency.

Detailed notes form the core. Diagrams, experiments, and visual explanations turn the notes into understanding.

Clear technical English

Defined terms, short explanations, worked examples, mental models, and common mistakes.

02 / SEE

Diagrams

Labelled devices, boundaries, and paths. See what changes at each step.

03 / TRY

Interactive HTML demos

04 / EXPLAIN

Animated explainer plan

A storyboard and narration that build intuition through original visual reasoning.

A simple way to study and take notes

Use an hour as a guide. Repeat a concept when needed; the goal is to explain and apply it.

One focused hour

  1. 20 minRead the explanation and work through an example.
  2. 15 minDraw the diagram and try the interactive demo.
  3. 15 minRun the exercise or investigate a failure scenario.
  4. 10 minWrite what you learned and list your questions.

Continue with the same lesson if the model is still unclear.

  1. What problem does this concept solve?
  2. How does it work, in my own words?
  3. Can I draw and explain one example?
  4. What did I change, and what happened?
  5. What evidence would help me diagnose a failure?
  6. What is still unclear?
